# 手键成绩扣分依据

个人岗位手键与手键组训共用 MessageComparisonService，结算时在每页原有 resolver JSON 内新增 deductionEvidence、timingEvidence。原始拍发记录及既有评分结果字段保留，数据库不新增列。

成绩页“扣分依据”按钮展示当前页：报底组号、拍发组号或连续组范围、标准报底、解析后实际拍发、按规则产生的扣分。点划/间隔异常额外记录拍发组号、字符序号、日志段序号、实际毫秒、允许的最小/最大毫秒和对应扣分。段序号按原日志编号，包含间隔段。

金额边界：逐组为封顶前金额，整场实际扣分直接使用已保存的 deductInfo。两个表明确区分，时长表是逐组扣分的原因，不能再次求和。速率加减分及整页未提交扣分属于整场汇总；页内缺行及解析拆分产生的扣分以本页整体事件表示。组/行位置为识别起点，不能误读为逐字符替换定位。

历史 resolver 没有这两个字段时提示缺少已保存依据，不从当前规则追算或修改旧成绩。需要后端加载新代码并重新产生结算结果，才有新明细。

样式调整：深色弹框、整场扣分卡片、报文对照与时长依据分区；扣分项用暖色突出，长表内部滚动及固定表头，小屏横向滚动。多少码条目说明任意位置插入/缺失后与报底一致，错码条目说明内容不符。模板渲染测试和ESLint通过，未作浏览器视觉验收。

调用面已核对 TelegramApi.js 的个人手键详情/取页、handkeyZuXun.js 的详情/取页，以及两侧 trainScore.js 对 resolver 的 JSON 解析。端点、参数、信封不变；只是 resolver 增加字段。组训页改为按页码保存 resolver，避免异步回包顺序影响依据定位。

验证：相关后端36项测试通过，包括定位、点划时长允许范围、封顶前6分而最终4分、改错及多少组去重。前端2项真实模板渲染测试通过，验证明细及旧成绩提示；ESLint无错误（组训原脚本2条未使用变量警告）。没有进行数据库集成与浏览器端到端结算验收。
