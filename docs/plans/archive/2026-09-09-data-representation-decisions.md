# 数据表示字段决策（Phase 8）

- 日期：2026-09-09
- 状态：字段清单审计完成；未做无证据的全站重命名。

## 1. 时间字段

| 场景 | 后端 wire 字段 | 前端消费 | 决策 |
|---|---|---|---|
| 理论/试卷 SQL 投影 | `start_time`、`end_time`、`create_time` | 直接按 snake_case 读取并交给 `moment`/`dayjs` | 保留。SQL DTO 与现有页面契约一致 |
| 普通 DTO/训练 VO | `startTime`、`endTime`、`createTime` | 直接按 camelCase 读取 | 保留。Jackson 默认属性与 Java DTO 一致 |
| 理论知识、试卷创建时间 | camelCase 字段内为 epoch 毫秒字符串 | `Number(...)` 后格式化 | 保留，避免把历史字符串改成日期字符串造成兼容回归 |
| 训练时间 | `LocalDateTime`，训练 VO 已使用 `@JsonFormat` 和 `GMT+8` | 直接展示 | 保留；新的训练 VO 继续显式时区 |

已确认的确定性错误 `startTime`/`start_time` 页面消费已在前序任务修正；剩余混合命名属于不同 DTO/SQL 投影边界，不进行全站替换。

## 2. 数值字段

- 评分、速度、统计数量在后端同时存在 `Integer`、`Long`、`BigDecimal` 和历史字符串字段。
- 前端图表和成绩页已经在需要数值运算的位置使用 `Number`/`parseInt`/`toFixed`；文本展示保留后端原始表示。
- 不把所有数字字段强制转换成字符串或数字。新增接口应使用明确的数值类型；历史 wire 类型只有在发现具体消费错误时逐项迁移。
- `NaN`/空值防御属于各消费点业务校验，不通过全局 coercion 隐藏错误。

## 3. 字典字段

- 设备类型、题目选项、训练状态等页面使用后端 ID/枚举值，显示文本来自当前页面字典或后端 DTO 映射。
- 不在共享层猜测未知枚举值；未知值保留原值并由具体页面给出降级显示。
- 本轮未发现可由统一字典改造安全解决的确定性跨栈错误，不新增字典协议。

## 4. createTime 与时区

- `createTime` 的 epoch 毫秒和 `LocalDateTime` 是两种已存在的 wire 契约，不能仅按字段名合并。
- 新增 `LocalDateTime` 返回必须显式格式和时区；历史 epoch 字符串消费保持不变。
- 服务端、MySQL、浏览器和 Electron 的部署时区仍需在部署验收矩阵中确认；仓内不通过隐式系统时区修改历史数据含义。

## 5. 验收结论

- [x] 已处理确定性时间字段错读：自测/考试页面使用真实 `start_time`，训练新 VO 使用 camelCase + 明确格式。
- [x] 已决定不做全站 snake/camel 或数值 wire 重命名，理由是现有 DTO 边界和页面消费契约不同，缺少统一迁移前提。
- [x] 已明确新增接口和字段的类型/时区规则。
- [ ] 生产时区、仓外 Electron 时区和历史数据全量抽样仍属于部署验收前置，不在仓内代码中虚构完成。
