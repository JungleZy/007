# 整合安装实施计划

对应规格：`docs/specs/2026-11-05-integrated-desktop-deployment-spec.md`。

当前进展：保持 Electron 30；已实现干净初始化资产生成、Windows x64 运行组件准备、数据库/后端生命周期管理、可写目录与只读资源回退。独立实例已验证首次启动、管理员登录、SQL 备份恢复及第二次启动保留数据。安装包与目标系统验收仍需单独记录，详见 `docs/guides/integrated-desktop-install.md`。

新增32位交付进展：按用户最新授权独立适配 Electron22 ia32、Liberica Java21 x86、MySQL5.7 Win32。已完成依赖下载校验、32位专用构建、迁移副本转换、备份参数、隔离数据目录及真实32位服务链验证。保留原x64产物；详见 `docs/guides/windows-ia32-install.md`。

2026-11-06 现场反馈：用户确认 compat2 在原报障的 **Win7 64位机器**上正常安装使用；相同环境的交付基线改为“生成ia32解包目录 → compat2封装”，完整步骤和反馈范围见 `docs/guides/win7-installer-system-dll.md`。Win7 32位操作系统及外设逐项验收仍待补充。

麒麟ARM64交付进展：用户已明确目标为银河麒麟V10桌面版，已交叉生成完整 `.deb`，包含Electron30 ARM64、Java21 AArch64和MySQL8 AArch64；安装包格式、依赖声明、架构/权限/摘要检查与组件QEMU版本启动检查通过，尚未在麒麟实机安装。见 `docs/guides/kylin-v10-arm64-install.md`。

## 1. 冻结兼容范围与组件组合

- 原x64分支保留Electron30；用户后续要求的Win7兼容分支采用Electron22 ia32＋Java21 x86＋MySQL5.7 Win32，并以compat2为相同环境的安装器基线。
- Windows交付包含上述x64和ia32两个分支；Windows ARM64不在当前范围。用户已验证的是Win7 64位系统运行ia32包，不能将其写成Win7 32位系统已验收。
- ARM64 首期仅针对国产 Linux，Linux x64 同时纳入；LoongArch64 后续独立适配。
- 现代 Windows x64、Linux x64/ARM64 分别记录 Electron、Node、JDK/native、MySQL、系统运行库、glibc、ABI 和摘要。
- Win7 64位故障机已有compat2安装使用成功反馈；记录该范围，其他Win7版本/架构及业务与外设场景继续单独验收。

退出条件：明确各目标的组件组合和已有产物，继续实现可执行部分；Win7 实测放在交付安装包后由用户执行。

## 2. 制作独立初始化资产

- 从当前实体、schema 与迁移提取干净初始化定义和必要基础数据；不复制已有用户、会话和训练记录。
- 定义首次管理员初始化流程及迁移版本标识。
- 在隔离数据库中验证 schema validate、初始登录和重复启动幂等性。

## 3. 绿色数据库与后端预置

- 获取可信的目标平台 mysqld 及依赖，生成组件清单并校验架构/版本/许可。
- 预置目标后端产物或 JVM，保证客户无需单独安装 Java。
- 打包前检查整套资源齐全；缺任一组件则阻止生成宣称“安装即用”的包。

## 4. 实现持久目录与生命周期管理

- 分离只读安装资源、可写配置、datadir、上传文件与日志。
- 将单实例锁前移，新增启动状态机、SQL/后端/文件服务就绪检查、失败提示和诊断入口。
- 管理首次初始化、凭据持久化、端口冲突与进程归属。
- 实现顺序退出与数据库正常关闭；不强杀未知进程。

## 5. 安装、更新与已有数据迁移

- 打包对应平台必需的运行库，安装后普通用户可运行。
- 将现有外部数据库迁移设为明确流程，不自动覆盖用户现有库。
- 验证升级仅替换程序资产，业务数据和配置保持完整。
- 保留协同部署的远程服务器连接能力。

## 6. 完整系统验收

- 逐目标干净环境离线安装、初始化、登录和核心训练。
- 音频、串口、文件上传、数据库备份与恢复。
- 二次启动、重复启动、异常退出后恢复、正常退出、带数据升级。
- Windows 7 x64、Windows 10/11 x64、国产 Linux x64/ARM64 必须有各自的实际运行证据；LoongArch64 后续独立验收。
