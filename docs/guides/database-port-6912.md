# 将内置数据库端口改为 6912

当前源码的新实例默认端口已改为 6912。升级启动时，旧默认 13306 配置会迁移到 6912；后端 JDBC 地址及 MySQL 配置由实例端口生成。手工设置的其他端口不自动覆盖。

## 已安装 fix1 的电脑

不用重新下载安装包，直接使用 `bw-frontend/out/数据库端口改为6912.zip`：

1. 退出软件，关闭错误弹窗。
2. 解压压缩包，双击 `set-port-6912.cmd`。
3. 出现 `PORT_6912_READY` 后，重新启动软件。

若软件安装在其他目录，把安装目录里的软件 EXE 拖到 `set-port-6912.cmd` 上运行。

工具自动找到当前用户的数据库实例配置，备份后只将 `port` 从 13306 改为 6912。数据库口令、管理员信息、实例状态及实际数据保留。软件下次启动时会自动重写 MySQL 配置并更新内部数据库连接，不用手工修改 `my.ini` 或前端网络设置。

目标 6912 被占用、软件尚未退出或本实例数据库进程仍在运行时，工具会停止修改；先正常关闭软件，必要时重启电脑后再执行。已是 6912 时重复运行不会再次备份或改写。

如果执行失败，请提供工具目录中的 `port-change-report.json`。

## 自动迁移的保护

新版本源码启动时检查新端口可用性。如果旧 13306 上的数据库可以用本实例凭据连接、真实数据目录一致且进程标识位于本实例目录内，则正常关闭旧实例并等待退出，再保存新端口并重启。旧端口被无关程序占用时不发送关闭命令。新端口不可用时不改写旧配置。

## 验证

- 8 个相关 Node 测试通过：端口工具字段保留、幂等、占用时拒绝修改、自动迁移的属主判定、关闭顺序及原有初始化保护等。
- 独立数据库实测：本应用 MySQL 在 13306 运行时，新源码正常关闭旧进程并切换到 6912，后端启动成功，标记数据和数据库凭据保持一致。
- 已安装版本实测：使用 fix1 归档中的旧启动代码，先关闭旧实例，再模拟其他程序占用 13306。通过已打包 Electron 执行端口设置工具后，旧代码读取保存的 6912 配置，数据库和后端成功启动，标记数据与凭据保留，无关的 13306 服务保持运行。
- 本次没有连接或修改正在使用的开发库 3306；验证数据均位于独立临时目录。

已发布的 fix1 安装包本身仍是旧默认值，存量用户使用上述工具即可。后续从当前源码构建的安装包默认使用 6912。
