## 二、代码质量问题

### 2.1 重复代码（严重） ✅ 已优化

**问题描述**：三个训练服务类存在大量重复代码，违反 DRY 原则。

| 文件 | 原行数 | 状态 |
|-----|--------|------|
| GeneralKeyPatService.java | 992行 | ✅ 已优化 |
| GeneralTelexPatService.java | 849行 | ✅ 已优化 |
| GeneralTickerPatService.java | 1003行 | ✅ 已优化 |

**具体重复点**：

1. **统计分数方法** - `statisticsScoreAndDotLineGapRate` 在三个类中几乎完全相同（约 90 行）
2. **报文生成逻辑** - 生成数字/字母/混合报文的代码重复出现
3. **添加训练用户** - 用户实体创建和 WebSocket 通知逻辑重复

**优化方案**：

创建了两个工具类来提取公共逻辑：

1. **[PatTrainStatisticsUtil.java](file:///d:/workspace/007/src/main/java/com/nip/common/utils/PatTrainStatisticsUtil.java)** - 统计工具类
   - 分数分布计算
   - 百分比计算
   - 用户成绩趋势构建

2. **[PatTrainStatisticsBuilder.java](file:///d:/workspace/007/src/main/java/com/nip/common/utils/PatTrainStatisticsBuilder.java)** - 构建器模式
   - 使用泛型支持不同实体类型
   - 函数式接口提取数据
   - 链式调用，代码更简洁

**优化后代码示例**：
```java
// 使用构建器模式重构统计逻辑
PatTrainStatisticsBuilder<GeneralKeyPatUserEntity, GeneralKeyPatTrainErrorCollect> builder =
    PatTrainStatisticsBuilder.<GeneralKeyPatUserEntity, GeneralKeyPatTrainErrorCollect>create(trainUserEntities)
        .withScoreExtractor(GeneralKeyPatUserEntity::getScore)
        .withUserIdExtractor(GeneralKeyPatUserEntity::getUserId)
        .withCreateTimeExtractor(GeneralKeyPatUserEntity::getCreateTime)
        .calculateScoreDistribution()
        .buildUserTendencies(
            userId -> {
              UserEntity userEntity = userService.getUserByIdNew(userId);
              return userEntity != null
                  ? new PatTrainStatisticsBuilder.UserInfo(userEntity.getId(), userEntity.getUserName(), userEntity.getUserImg())
                  : null;
            },
            (userId, createTime) -> trainUserDao.findByFistTwoScore(userId, createTime)
        );

// 封装结果
ret.setSchoolReport(builder.getSchoolReport());
ret.setUserTendencyVO(builder.getUserTendencies());
```

**优化效果**：
- 消除约 200 行重复代码
- 统一统计逻辑，便于维护
- 支持泛型，可扩展到其他服务类

private void countScore(PostTelegramTrainEntity entity, PostTelegramTrainFinishDto dto) {

for (int i = 0; i < cableFloor.size(); i++) {
    for (int j = 0; j < cableFloor.get(i).size(); j++) {

## 五、安全问题 ⏸️ 暂不处理

### 5.1 密码存储使用 MD5（严重） ⏸️ 暂不处理

**问题位置**：MD5Util.java

```java
// 问题：MD5 已不安全，容易被彩虹表破解
public static String encrypt(String source) {
    return encodeMd5(source.getBytes());
}
```

**优化建议**：使用 BCrypt 或 Argon2
```java
// 使用 BCrypt
public static String encrypt(String password) {
    return BCrypt.hashpw(password, BCrypt.gensalt(12));
}

public static boolean verify(String password, String hashed) {
    return BCrypt.checkpw(password, hashed);
}
```

**处理说明**：经评估，当前系统已上线运行，密码存储优化涉及用户数据迁移，风险较高，暂不处理。

### 5.2 Token 生成方式不安全 ⏸️ 暂不处理

**问题位置**：UserService.java:383

```java
// 问题：Token 包含敏感信息（密码），且使用 AES 加密不够安全
String token = AESUtil.encrypt(userAccount + "-" + password + "-" + deviceId, AESUtil.UKDAI_AES_KEY);
```

**优化建议**：使用 JWT（项目已引入 smallrye-jwt）
```java
String token = Jwt.issuer("nip-app")
    .subject(user.getId())
    .claim("account", userAccount)
    .claim("deviceId", deviceId)
    .expiresAt(System.currentTimeMillis() + 3600000)  // 1小时过期
    .sign();
```

**处理说明**：经评估，Token 优化涉及客户端兼容性，暂不处理。

## 九、总结

本项目存在以下主要问题：

1. **代码重复严重** - 三个训练服务类存在大量相似代码，维护成本高
2. **方法过长** - 多个计分方法超过 100 行，最长达 580 行
3. **异常处理不规范** - 大量使用 `e.printStackTrace()` 而非日志框架
4. **安全隐患** - 密码使用 MD5 存储，Token 包含敏感信息
5. **类职责过多** - Service 类承担了业务逻辑、数据转换、通知等多种职责
