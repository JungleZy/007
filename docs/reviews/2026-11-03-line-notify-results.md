# 线路通报：拍发人员复盘收报结果与本人拍发记录

## 行为与权限

- 用户确认：拍发人员查看本房间所有频道的收听人员结果。
- 房间结束（stats=2）后，拍发人员可点击已完成的收听人员，分页查看其答案，并切回“查看我的拍发记录”。进行中仍禁止普通拍发人员读取他人答案。
- 接收人员在房间结束后，可从发送人列表打开本房间任意拍发人员的记录；组训人也可读取已结束房间的拍发记录。外部人员、其他房间目标均拒绝；保存仍限定本人拍发记录。
- 组训端“发送人分组”补齐逐人查看按钮，组训端与接收端共用 `PatRecordDialog.vue`。按用户最终要求，弹框固定780px高，小窗口下限制为视口高度减48px，距离顶部24px。标题、波形和译码设置固定，译码区弹性占用剩余空间并在内部滚动，外层正文不再纵向滚动；底部保留24px内边距。
- 后端按真实房间成员角色校验，只放开收报答案读取，不将线路通报拍发人员提升为组训人；收听人员、外部人员的原有权限继续生效。
- 收报提交后的结果通知同步发给拍发人员，断线恢复仍通过 REST 回读。
- 本人拍发记录包含按下时长 diff、前置间隔 gap（毫秒，保留小数）及 pageNumber。每 5 秒合并保存，发送完成前确认保存；本机未保存缓存用于失败重试与刷新恢复。
- 服务器对已保存快照只允许追加，旧快照重试不截断新记录，冲突快照拒绝。保存时属主取 token，不接受客户端指定记录属主。
- 拍发端与接收端共用 PatRecordPanel：波形保留横向滚动条，滚轮可横向移动，滚动到边界后交还页面滚动。新增记录仅在原本处于末端时自动跟随；系统译码区可纵向滚动。
- 系统译码复用 useMorse 的短码、长码、字母和混合码表，按前置间隔分字/分组，跨页断字，忽略不超过 10ms 的微按压且保留其间隔时间；未知点划显示“#”，不按报底补字。仅供复盘，不改写原始采集或收报评分。
- 用户反馈整段合成一组后，确认此前固定 5000ms 的组间分界错误。现与个人岗位手键共用 `common/utils/handKeyTiming.js`：点划分界为 dot×(1+skew/100)，字间分界为 codeGap×(1+skew/100)，组间分界为 codeGap×(3+skew/100)；间隔严格大于分界才分字/分组。默认 dot/codeGap=80ms、skew=50%，对应 120/120/280ms。面板调整项改为点基准、码间隔基准及偏移百分比。岗位手键的原有试机校准和基准更新流程继续使用该公式；线路通报复盘按面板基准读取已有原始记录。
- 随后实际记录复核发现仅统一公式仍不够：房间87已保存311次按键，点约42ms、划约121ms、字间约132ms、组间约215ms。固定80ms基准会将部分划判成点，并漏掉组边界。现面板默认自动校准：优先按开始符10001的实际点/划和码内间隔恢复基准，没有完整开始符时用真实时长分布估计；可切为手动调整。80ms仅用于无有效记录时的初值。
- 自动校准实测得到 dot≈41.33ms、line≈121.8ms、codeGap≈41.65ms；对311次原始记录的译码分组与按测量值 dot=42/codeGap=43 复核的分组一致，开头为“开始 / 7287 / 2410 / 2393”，未识别字符为0。此验证不以报底内容纠正实际拍发。
- 控制符与岗位手键共用 `common/utils/handKeyControlCodes.js`，复盘展示开始、结束、换页，当前组改错直接显示 `?`、前一组改错直接显示 `/`；三截00须各自独立成组才合为换页。复盘保留原始拍发顺序和索引，不把展示控制符当成训练操作再次执行。
- 拍发人员自己的PatRecordPanel启用followLatest，初次加载及每次译码更新后，在DOM更新完成时把译码框滚动到底部，即使当前选中了较早的波形也继续显示最新报文。组训/接收人员弹框不启用该选项，保留查看者的滚动位置。
- 译码按实际组间间隔分块，不强制每四字一组。每个字符保留原始按键索引范围，点击字符（包括未识别的 #）会按实际 DOM 位置滚动到对应波形并高亮，兼容微按压过滤、长间隔压缩及当前已有滚动偏移。选中记录后，新到的按键不再将视图拉回末尾。
- 此前只存于页面内存、已经丢失的历史拍发记录无法重建。
