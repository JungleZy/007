# 全项目复核整改规格（2026-09-15）

来源：[review](../reviews/2026-09-15-full-project-review.md)；执行：[plan](../plans/2026-09-15-full-project-fix-plan.md)。R01–R19 为独立跟踪标识；本规格经独立审阅后实施，运行补验发现的边界追加取证和补审。

## 1. 不变约束

1. 203/204/206 鉴权码值与文案不变，REST token/deviceId 仍只走请求头；WS 握手规则不变。授权拒绝 207，终态拒绝 208，业务结果用既有 HTTP200 信封。
2. `is_admin=0` 才是管理员。前端 v-per 不构成服务端授权。所有新增授权从认证主体推导，不能信任客户端 userId/roomId 声明身份。
3. 采集/时钟/评分使用服务器持久来源；冻结评分规则、attempt 栅栏、行锁、幂等与提交后通知不得回退。事务异常不得吞掉后部分提交。
4. 跨栈字段、返回形态和单位变更必须同步全部实际消费者和相关回归；导出符号先查引用。当前无 LSP，记录搜索替代证据，不伪称语言服务器已验证。
5. 历史协议行不伪造时间轴，不抬升 protocol，不重写历史成绩。实体/schema 变化附增量迁移并验证 current/base 双快照；已执行迁移不得重写替代新迁移。
6. `keysim/src/console.rs`、`serial.rs` 的外部并发改动不覆盖、不代提交；模拟器独立版本和产品版本不强行合并，不新增 release 资产。
7. 已定义的业务失败（参数/鉴权/授权/终态）使用HTTP200+业务code；现有未处理系统故障保持HTTP500+code500，JAX-RS协议异常保持原HTTP状态。依据GlobalExceptionMapper、WebApplicationExceptionMapper及ExceptionBoundaryTest既有契约；不改mapper掩盖R01根因，R14澄清“恒200”的笼统文档。

## 2. 逐项行为与验收

### R01 经典手键一致结算

- 作用域：`TelegramTrainService` 的提交、暂停/结束、`saveFloorContent` 单内容写入、原始结果重算与当前页恢复。
- 受管内容记录在本事务内更新；重算读取本次已授权提交的最终内容。不能用无差别 clear 持久上下文丢弃其他待提交状态。
- 暂停与结束先结清本次活动毫秒，再算码率。统一 `ScoreMath.rate/accuracy`，避免无限精度字符串写超 `speed varchar(11)`；分母为 0 的现有防护保留。
- 暂停/结束当前页必须属于该训练。省略页指针保留已有合法指针；失败无写入。
- protocol 0 非终态旧行开始、暂停、结束均按既有历史只读契约拒绝；不得从可开始变成无法结束的软锁。
- `saveFloorContent` 同样锁定所属训练行，先验证属主、protocol1及未结束状态，才更新受管答案；保留新协议草稿/进行中/暂停的合法保存，历史或已结束行208且无写入。既有成功fixture须显式声明合法新协议，而非继续用默认protocol0。
- 真实经典单字载荷是裸单字符moresKey（含数字）与平面码元数组；词组载荷是JSON字符数组与二维码元数组，按冻结训练/报底类型解析。数字按floor.numberType=0长码/1短码；不把裸数字误读为JSON数字后丢弃。每个报文条目为一个练习单位，词组须整组匹配；总数/正确率按条目，码率按实际有拍发内容的条目计时，未拍发条目不制造速度。
- 实际WS code3001采集必须以WebSocketHandshake认证身份进入同一受管写路径、同一训练锁及属主/protocol/终态守卫；不能保留WebSocketEventService裸bulk更新。旧会话不得继续写；同一采集入口的code2001日志也必须验证训练属主/可写状态并由服务器生成ID/时间。失败回复现有业务code，不能只在异步日志里吞掉。回归覆盖真正单字A、短码数字、四码词组，以及WS外人/终态拒绝和采集/结束竞争。
- 验收：首次正确提交立即正确评分；部分错误与全错准确；两次活动段之和计时且暂停不计；第一暂停码率不再滞后一轮；重入定位当前页；生产库真实结束不再 SQL1406；伪造客户端指标无效。

### R02 组训手键缺报

- 每个缺页 p 的组数为 `min(100, messageNumber-(p-1)*100)`，只处理合法页号。
- 返回 lack 和喂给缺组扣分的增量源自相同值，保留已经识别的页内少组计数。
- 验收：100 全缺=100；150 仅末页缺=50；250 缺第1/3页=150。用未封顶规则验证实际扣分，满页正确提交不回退。

### R03 岗位手键复盘页对齐

- 保持 detail 现有返回字段，不新增兼容别名。所有页级展示数据以同一页号排序；未提交页的分析采用消费者能正确识别的空分析占位。
- 验收：第1页未交、第2页有错码时，第1页显示未提交，第2页显示自己的错情；不因数组错位误贴解析。常规顺序两页结果不变。

### R04 岗位电子键正确率

- 正确组数按拍发组减去同源解析的错码、串组、少码、多码，走 ScoreMath 现有钳制与精度。
- 不更改扣分规则、原始采集格式、attempt 或服务端速度单位。
- 验收：全少码、全多码不再 100%；正确和错误混合得对应比例；与组训同样输入的正确组定义一致。

### R05 数据报开始确认

- `saveTest(status)` 返回完成信封校验后的 Promise<boolean>。仅 code200 为 true；业务拒绝/网络失败为 false，保持可恢复输入和可重试开始状态。
- `beginTrain` 在服务端确认后才置进行中、启动唯一计时器并结束首次键监听；失败不得伪装开始，重复按键不得制造并发开始或重复计时。
- 验收：真实页面首次键无 TypeError，服务端与前端均进行中，计时递增；断网/207/208/普通失败不丢输入、不启动计时，允许的重试可成功。
- 结束定稿与开始确认分离：结束快照一旦提交，在结果不确定期间保持可见且冻结所有实际输入路径，重试只重发同一快照；不得让用户编辑新答案后静默重放旧pending并覆盖新输入。

### R06 收报恢复单位

- 服务端 `validTime` 继续为秒字符串；在进入前端毫秒拆分函数处唯一转换。
- 验收：120 秒恢复为 00:02:00；继续计时从该值递增；0 和超过一小时均正确。不更改后端存储或重复累加暂停时间。

### R07 数据报逐页分析时长

- `patDetail` 及公共分析生成路径从该用户该页的持久 captureIntervals/capturePages 获取有效毫秒，复用现有 CaptureTimeline 校验/求和，不使用用户上送聚合。
- 一页多次扩展使用最终确认区间，重试不重复计入。部分完成、空页、历史缺采集证据需明确为空/零的语义；不得给缺证据页伪造正数。
- 前端可达消费者以毫秒字段计算有限码率，零时长显示现有无数据状态；不是仅把 Infinity 钳制掩盖服务器恒零。
- 逐页patNumber在本数据报分析域明确为正文字符数，复用characterCount剔除命令/地址，与CHARACTERS_PER_MINUTE权威码率一致；不使用组数或简单乘4。1250ms的正文1234 5678为8字符、384码/分，附加QTA命令不改变正文分子。
- 验收：非空有效采集页的 totalTime 等于其有效区间长度且码率有限；两页分别取自己的时间；未提交/历史无采集数据不产生 NaN/Infinity。

### R08 仿真房间权限

- 写端点：`/simulation/router/changeChannel`、干扰报 `saveSetting`。读端点：`getRoomChannels`；无前端消费者的调试全房间清单 `getAllRoomInfo` 使用现有管理员门禁。

### R09 个人汉字录入权威结果

- **个人域是拼音/五笔码串条目练习，不是岗位汉字/英文录入。** type0同字异音、1同音异字、2连音词组、3军语词组、4文章、9五笔；不得套用岗位域相同数字的含义。仅复用属主、行锁和活动时钟模式，不复用岗位font/value评分。
- 服务端在创建时从词库与规范码表冻结每条font及期望码串：type0采用词库已有pys消歧；其他拼音遵循现有Homophone首匹配规则；五笔遵循fontBank及现有lastIndexOf选码规则。规范码表提取为一份共享JSON，由现有前端模块及Java打包资源共同消费，不手写第二份不同读音规则、不信任客户端提交的py。
- 默认词库的缺字必须有来源地补全，而非忽略词条或发明五笔码：仅补既有`pinyin 2.11.2`默认读音和`qq-wubi 1.0.0`唯一完整四码覆盖的缺失汉字，所有已有首/末匹配保持原值。ASCII及键面符号走共享`keyboard.inputKeys`，ü/带调ü规范为v；这不是给拉丁字母伪造五笔码。未来仍未有码的字符逐字明确202，不能拼接空串悄悄消失。
- 新作答契约在每个原有content条目中保存实际输入码串`value`（字符串），服务器根据冻结期望重算pys展示状态/正误，不采信trueOrfalse。输入长度给出当前条目进度，未完成条目保留实际输入；source/font/py不能被作答覆写。前端pinyin/practice、wubi/practiceTwo及其文章键盘组件全部迁移。
- 保留“条目/组”计数：输入完成期望码串长度才成为已完成组；完整相等为正确组，其余完成组为错误组；部分/未作答组不进入正确率分母但保存进度。速率为完成组/活动分钟，duration对外与个人统计为秒，内部活动段为毫秒。客户端accuracy/speed/duration/correctNum/errorNum不落权威值。
- 初始化不再调用pause伪装保存题面；服务器直接返回可渲染题面。开始、暂停、继续、结束有锁和状态守卫；重入恢复value而非重新生成空答案。重复结束相同答案幂等，不重复计时/统计；不同答案208。
- 新增协议/活动时钟/冻结题面字段使用独立2026-09-15-01-entering-exercise-clock.sql；旧非终态行提示重新训练，创建新训练不通过原“自动完成上一暂停条目”分支改写protocol0或制造统计；旧已完成记录仍可读。
- 验收：同字异音（如type0词库给定le/liao）、多字拼音词、type9五笔、错误按键、部分条目、文章逐条进度均按码串计组；伪造trueOrfalse/py无效；暂停不计时，重入保留实际输入；旧行/越权/终态无副作用。

### R10 理论考试生命周期

- 明确矩阵：type1是进行中考试的合法离场保存，仅允许未交卷考生且保留startTime；type2允许未交卷考生首次入场/重入，重复不重置时钟；type3为首次交卷。未知type202；已交卷/全场state3或4后的type1/type2/自动保存208。
- 保留成员通过teacherStartExam(type2)合法首次启动的能力；前端必须等待启动200再发学员type2，不依赖两个HTTP请求到达顺序。state3/4不能重新启动。
- **采用服务器硬结束语义**：现有teacherStartExam(type3)立即将全场及考生置结束，未实现服务器30秒收尾授权。本轮移除前端单独的31秒补交/虚假“已提交”提示；教师结束通知后停止输入和自动保存，读取服务器最后接收的答卷，明确提示本地未确认内容不能再提交。已经提交的本人答卷不再次离场保存。
- `teacherStartExam`、`studentChangeExamState`、`saveUserRealTimeParam`、`finishSelfTesting`、`TheoryKnowledgeExamUserService.teacherUploadScore` 均按exam→examUser一致顺序锁定，在锁内重读状态；结束/阅卷不能被迟到保存覆盖。
- 不可逆的考试开始/结束状态通知在事务AFTER_SUCCESS阶段发送不可变快照，回滚不得通知学员硬结束。合法无teacher自测不发送虚构监考通知，也不能因sendInfo(null)阻止入场。验证真实省略teacher的创建流程和结束事务回滚时无通知。
- `finishSelfTesting` 只允许token本人且考生行isSelfTesting=0的真实自测，按examId+actor取唯一记录；普通考核不得经该接口改content/score或转成自测。活动态首次结算，同内容重试不改endTime/score，不同答案208；自测创建不得接管普通考试。
- 必改消费者包括startTest/js/startTest.js与相关倒计时/离场、自测studentStartTest；R10先处理状态与顺序，R11后处理paper投影，共享文件串行。
- 验收：合法离场重入、首次启动请求顺序、教师硬结束后的真实学员页面、交卷/阅卷后覆盖、普通考核调用自测finish、已完成自测改答案、阅卷与迟到保存交错均覆盖；拒绝后答卷/状态/成绩不变。
