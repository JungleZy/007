# 个人岗位手键拍发：浏览器注入时序与前端性能复核

用户现象：字码偶发合并为 `#`、漏码。已确认使用浏览器注入；读取模拟器界面得到手键、短码、120 字/分、human、1 倍速、开始符开启、自动改错关闭。没有取得故障发生瞬间的浏览器性能录制，因此不能把截图中的每一处错误归因到某个特定长任务。

## 链路与确认的问题

链路：`keysim/src/serial.rs` → WebSocket `/ws/serial` → `keysim/public/inject.js` 的虚拟 ReadableStream → `WebSerial.handleData` → `publishTrafficFrame` → `createHandKeyDecoder` → 个人岗位 `details.js` → Vue 波形/正文。

1. 旧注入通道只传字节，不传源时刻；WebSerial 用主线程处理数据时的 `performance.now()` 当边沿时刻。主线程阻塞后集中处理多个消息，可把按压压成 0ms，随后被解码器的 ≤10ms 抖动过滤丢弃，也会扭曲字间隔。测试已复现。
2. 个人岗位每个点划安排滚动、读取滚动尺寸；成字/成组又同步读取布局。采集与界面工作处于同一主线程，渲染开销直接影响下一条消息的处理时间。
3. 每组校准用 `filter` 遍历全部历史，只保留当前游标后的新记录，造成无必要的随历史增长的扫描与响应式访问。
4. 模拟器原先按绝对计划时刻追赶。发送线程阻塞后，会快速补发后面的边沿，压缩真实间隔。TCP 回放测试注入 180ms 的阻塞后已验证新流程不压缩后续边沿。

## 修改

- 注入 WebSocket 在每个二进制字节帧前附文本时序帧，携带发送端实际单调时刻与本次拍发的时钟标识；不是用计划时刻替代实际时刻。旧注入器忽略文本帧，真实串口字节协议不变。
- 新注入器以 WeakMap 保存每个字节块的时间，通过虚拟端口 `getFrameTiming(bytes)` 供 WebSerial 读取。解码使用源时刻，`receivedAt` 继续使用页面单调时钟，避免与采集提交时钟混用。
- 注入器可识别并替换旧版本；重新注入后需重新连接其端口。
- 波形按 requestAnimationFrame 发布快照并合并滚动；采集、成字、成组继续逐事件执行。卸载时取消显示更新，后台暂停绘制不影响记录。
- 内部采集缓存改为 shallowRef；每组校准只 slice 新段，换页后释放已处理的校准缓存。
- 模拟器晚醒时顺延后续发送，保持相邻事件的计划间隔，不突发补发；控制台实测码率按实际发送时刻计算。

## 浏览器局部基准

使用独立诊断标签页、生产 `details.js`/解码器/校准函数和 Vue 波形、正文 DOM，模拟器生成 99 组 human 短码，共 3,574 帧。每 10 帧让出任务，最后等待显示更新完成。基线通过反向恢复本次局部性能改动构造。它是受控积压处理微基准，不是用户完整页面的现场性能录制。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 接收回调累计耗时 | 264.5ms | 167.6ms |
| 接收回调及同步 Vue 更新累计耗时 | 2020.5ms | 277.9ms |
| 上述单帧耗时 P95 | 1.3ms | 0.3ms |
| 上述单帧耗时最大值 | 17.9ms | 1.2ms |
| 滚动尺寸读取次数 | 4068 | 704 |
| 最终 DOM 节点数 | 251 | 251 |
| 解码组数 / 未知符号数 | 99 / 0 | 99 / 0 |

修改后的累计接收耗时不包含延后的动画帧绘制，不能用此表宣称整个页面 CPU 消耗同比下降。对照说明的是采集回调路径缩短、布局读取减少、结果未丢失。

## 验证

- `npm test`：135 测试通过。
- `node scripts/check-hand-corrections.mjs`：12 种模拟器真实帧与个人岗位成字逻辑对照通过，包括 201 组、跨页、手工及自动改错。
- `cargo test --test hand_pagination --test hand_corrections --test electron_pagination`：14 测试通过。
- `cargo test --lib serial::tests`：发送线程阻塞、时间帧与字节帧对应关系测试通过。
- ESLint 无错误，个人岗位 details.js 有 3 条已有未使用变量警告。
- 扩大运行 `cargo test --lib` 时，已有安装提示测试 `install::tests::manual_command_is_absolute_and_runnable` 在 Windows 因期待 Unix 命令失败；不能宣称全 Rust 套件通过。

## 验证边界

真实 COM/硬件协议没有源时间戳，主线程积压后无法从普通字节恢复已经丢失的时间信息。本次前端性能优化对其同样有帮助，但注入端时钟修复不能替代真实设备验证。发送端操作系统暂停仍会延长当前点划；新流程避免用后续突发补发放大失真。尚未以用户原始故障报文完成完整训练、评分接口和现场设备的回归验收。
