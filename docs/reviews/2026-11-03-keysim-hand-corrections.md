# 模拟器手键改错符与重发

## 用户确认与使用方式

用户要求同时支持报文输入框手工输入，以及自动模拟并重发。

| 输入/选项 | 行为 |
| --- | --- |
| `?` | 发送当前组改错符 `001100` |
| `/` | 发送前一组改错符 `001011` |
| 当前组改错并重发 | 自动选择位置发送当前组改错符，重发该组 |
| 前一组改错并重发 | 自动选择位置回退前一组，依次重发前一组和当前组 |

手工符号支持组内和组结束之后的位置，后面需写出重发正文。例如：

- `12?1234 5678`：在首组拍出12后改错，重发1234，再发5678。
- `1234 ? 5678`：首组结束后改错该组，改发5678。
- `1234 5678 / 9012 3456`：两组结束后回退前一组，依次重发9012和3456。

自动选项可以同时勾选，也可与手工符号组合使用。位置和次数由种子确定，同种子同报文可复现；每种已启用且存在可用位置的模式至少触发一次。单组报文没有自动回退前一组的位置，预览会如实提示。

CLI新增 `--correct-current`、`--correct-previous`。网页API参数为 `correctCurrent`、`correctPrevious`；预览返回 `corrections.current/previous` 次数。电子键不启用这两个手键选项。

## 与个人岗位手键的对应

依据 `bw-frontend/frontend/src/views/manage/postJob/telegram/train/js/details.js`：

- 当前组已有字时，当前组改错不退组，前一组改错退1组。
- 当前组已经结束、组游标指向下一空组时，当前组改错退1组，前一组改错退2组。
- 回退钳制到当前页首组，不回到已提交的上一页。
- 控制符与正文均按真实按下/抬起时间轴发送。组内手工改错前使用字间隔；组完成后的改错前使用组间隔。
- 上传载荷保留与客户端一致的逐组历史及 `?` 标记，同时保留控制符的点划与时长。

`keysim/src/hand_script.rs` 统一解析手工脚本、插入自动重发并维护逻辑组游标；`keying.rs` 负责转换为事件时间轴。分页按逻辑组位置推进，重发不增加新组计数。第100组后的手工改错先完成，下一页正文真正开始时再发送分页符。
